# 从公开源码复现

## 环境与依赖

本项目针对微雪ESP32-S3-Touch-AMOLED-1.75C，使用32MiB Flash、Octal PSRAM和466×466 AMOLED；不要刷到其他型号。

安装Git、Python和[ESP-IDF v6.0.2](https://github.com/espressif/esp-idf/tree/v6.0.2)。按照[Espressif官方安装指南](https://docs.espressif.com/projects/esp-idf/en/v6.0.2/esp32s3/get-started/index.html)准备ESP32-S3工具链，然后在构建终端激活IDF：Linux／macOS使用其`export.sh`，Windows使用ESP-IDF终端。

`main/idf_component.yml`声明依赖，`dependencies.lock`固定传递依赖和校验值：官方1.75C BSP 3.0.0、LVGL 9.5.0、LVGL Adapter 0.4.3、cJSON 1.7.19~2等由Component Manager下载。`sdkconfig.defaults`和`partitions.csv`提供板端配置；本机生成的`sdkconfig`与构建目录不会提交。

## 构建

```sh
./scripts/build.sh --build-dir /tmp/chameleon-pet-build
```

使用无空格的ASCII绝对构建目录。输出在`dist/`：bootloader、分区表、应用、完整镜像、刷写参数、构建信息和SHA256清单。`main/chameleon_assets.c`和`main/chameleon_font.c`已经包含全部板端图像及字体，可以直接编译；通常无需重新制作图像资源。

`cmake/chameleon_adapter.cmake`调用已包含的`prepare_standby_adapter.py`，生成三份适配器修订代码并参与编译，不修改官方托管组件。

如果需要打包，先提交自己的源代码修改、从干净工作区构建，再运行：

```sh
python3 scripts/package.py
python3 scripts/verify_flash_inputs.py dist
```

构建依赖已固定，但工具版本、编译路径和构建日期可能影响最终二进制字节；复现目标是完整功能与一致的配置，不承诺不同机器生成相同SHA。

```sh
./tests/run_chameleon_tests.sh
./tests/run_chameleon_forest_checks.sh
./tests/run_chameleon_games_checks.sh
./tests/run_chameleon_alarm_checks.sh
./tests/run_chameleon_audio_checks.sh

```

原生C++规则检查需要C++17编译器，原生LVGL检查还需要CMake及已下载的托管LVGL组件；它们不操作开发板。

## 可选图片资源重建

源码包含三个阶段的实际动作帧、原图与转换参数，以及MIT许可的固定PixelArtConverter核心。重建素材需要Python3.12、Pillow12.3.0、NumPy2.3.5、SciPy1.16.3；字体转换另需Node、lv_font_conv1.5.3及SourceHanSansCN-Normal字体，按脚本中的固定路径准备在`.tools/`。这一步只供修改素材，普通固件构建不需要。

生成记录保留项目内相对路径和资源校验，机器生成路径、会话标识及其他本机信息已移除。发布者的环境、存档和旧提交历史不属于复现所需内容。
